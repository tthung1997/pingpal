# Contributing a character pack

A pack is a swappable character: a sprite sheet plus a `pack.json`. Nothing outside the pack loader
knows what the character looks like, so a new pack never needs code changes. This page covers what a
pack must contain, how to make it look right, and what a pull request needs. The manifest reference
lives in [DESIGN.md](DESIGN.md#4-character-packs); this page is the practical guide.

## 1. The animation model

Every character plays exactly three kinds of animation, so a pet, a person or a robot all fit:

| Kind | Required | When it plays | Design notes |
| --- | --- | --- | --- |
| `idle` | yes | Whenever nothing else happens, and while the user drags the character | Loops forever. Calm and low-key: it is on screen almost all the time. |
| `attention` | yes | Whenever a message is waiting, **until the user checks it** (clicks the bubble or the character, answers a question), which can be minutes | **Neutral.** Never happy or sad: the app does not judge whether the news is good or bad. Must loop smoothly, and stay calm enough to bear for a long time: no flashing, no big motion. |
| breaks | no, but bundled packs need at least one | One random break, 3-6 s, after each 6-14 s of idle; never the same one twice in a row | Short variations (nap, stretch, snack). Each break loops several times, so frame 4 must flow into frame 1. |

A message interrupts anything, including a break, and attention stays until the user checks the
message. Back-to-idle always follows, so every animation must start and end on a pose close to idle.

Design rules that make a pack feel good:

- **Stay put.** Keep the body, furniture and camera identical across animations and change only
  small parts (a paw, the eyes, a prop). Big shifts between animations read as the character
  teleporting. `corgi_desk` redraws one shared base per frame and swaps only the paws, face and props.
- **2-4 frames per animation** is plenty. Smooth, minimal motion beats many frames.
- **Suggested fps:** idle 3-6, breaks 2-4, attention 5-6.
- **Do not rely on hearts, "!" or sad faces** to say good/bad news. Attention only means "look here".

## 2. Files

```
packs/<id>/
  pack.json         manifest (see below)
  sheet.png         the sprite sheet
  sheet.png.import  generated by Godot on first import; commit it
tools/art/<id>.js   LibreSprite script that builds sheet.png (recommended for bundled packs)
```

To use a pack privately, put the same folder in `user://packs/<id>/`
(`%APPDATA%\PingPal\packs\<id>` on Windows). A user pack overrides a bundled pack with the same id,
and the PNG is read directly, so no editor or import step is needed.

### `pack.json`

```json
{
  "schema": 2,
  "id": "corgi_desk",
  "name": "Corgi at Desk",
  "author": "PingPal",
  "description": "One sentence on the look and the animations.",
  "sheet": "sheet.png",
  "frame_size": [89, 131],
  "anchor": [44, 129],
  "behavior": { "idle_seconds": [6.0, 14.0], "break_seconds": [3.0, 6.0], "breaks": ["bone", "sleep"] },
  "animations": {
    "idle":      { "row": 0, "frames": 4, "fps": 6, "loop": true },
    "bone":      { "row": 1, "frames": 4, "fps": 4, "loop": true },
    "sleep":     { "row": 2, "frames": 4, "fps": 2, "loop": true },
    "attention": { "row": 3, "frames": 4, "fps": 5, "loop": true }
  },
  "states": { "idle": "idle", "attention": "attention", "bone": "bone", "sleep": "sleep" }
}
```

- `id` is a simple, folder-safe name and must equal the folder name.
- `animations` name a run of frames on the sheet: `row`, optional `start` column, `frames`, `fps`,
  `loop`. Several animations can share a row via `start`.
- `states` maps what the app asks for (`idle`, `attention`, and each break name) to an animation. A
  break name must map to an animation other than idle. States left unmapped fall back to idle.
- `behavior` is optional; omitted keys use the defaults shown above.

The loader rejects the pack with a precise error for: a wrong `schema`, a bad `id`, a missing sheet,
an animation outside the sheet, `idle` or `attention` not mapped, a break that maps to nothing or to
idle, and a state pointing at a missing animation.

## 3. The sprite sheet

- PNG, RGBA, **transparent background with hard edges** (alpha 0 or 255, no soft shadows or
  antialiasing), nearest-neighbour friendly.
- A grid of equal cells: width is columns x `frame_size[0]`, height is rows x `frame_size[1]`. One
  animation per row is simplest. Unused cells stay transparent.
- **Cell size:** the app draws the art at 2x by default, and the speech bubble and status tray stack
  above the character inside a 420 px strip. Keep cells at or under roughly 130-150 px tall, and leave
  a few transparent pixels around the art so a prop never touches the cell edge.
- **`anchor`** is where the character's feet touch the ground, in cell pixels. Keep its x near the
  horizontal centre: the character is flipped around it (see below) and the drag limits use half the
  cell width.
- **Hit area:** the clickable region follows the visible pixels of the *current frame*, so empty
  space in a large cell never blocks clicks on windows behind it. Do not add faint or stray pixels
  far from the character: they enlarge the clickable (and drawn) area.
- **Mirroring:** dragging the character left mirrors the sprite horizontally, and it stays mirrored
  until it is dragged right again. Art with text, a logo or a one-sided prop will flip. Either design
  it to survive mirroring or keep such details small and symmetrical.
- **Front-facing is fine.** The corgi packs look toward the screen; characters do not have to be in
  profile or walk.

## 4. Pixel-art style

PingPal's art is pixel art made with [LibreSprite](https://libresprite.github.io/).

- Draw on a true pixel grid at native size. Never rescale or blur an image into a sheet.
- One consistent 1 px dark outline colour around the character and any props.
- A small shared palette (a few shades per material: shadow, mid, light, highlight). The bundled
  corgi sheet uses 32 colours.
- Every frame in a pack shares the same palette, lighting direction and level of detail.
- Check readability at the real size: view the sheet at 2x and at 1x, against both light and dark
  desktops.
- Only submit art you made or have the right to contribute. Do not copy existing characters or
  trademarked designs. If you used generated references, say so in your PR.

## 5. Building the sheet with LibreSprite

Hand-drawing in the LibreSprite GUI and exporting a PNG is fine. For bundled packs, a script that
rebuilds `sheet.png` from code is preferred, because re-running it reproduces identical pixels and a
reviewer can diff the art as text. `tools/art/build.py` runs such a script headless:

```powershell
python tools/art/build.py corgi_desk             # runs tools/art/corgi_desk.js, writes the sheet
python tools/art/build.py --proof corgi_desk     # one frame into local/, leaves the real sheet alone
python tools/art/build.py --no-run corgi_desk    # only write tools/art/dist/corgi_desk.bundle.js
python tools/art/preview.py packs/corgi_desk/sheet.png local/preview.png 4   # enlarged preview
```

Set `LIBRESPRITE_EXE` if LibreSprite is not on `PATH`. The build fails with the script error if
LibreSprite throws, so a blank sheet always means a real error (typically a colour name missing from
the palette object). Needs `python` and Pillow.

A sheet script starts with directive comments that the bundler reads:

| Directive | Meaning |
| --- | --- |
| `// @open <png>` | The document the script edits, relative to the repo root (e.g. `packs/<id>/sheet.png`) |
| `// @canvas <W>x<H>` | Start from a blank sheet of this size every run, so stale pixels never survive |
| `// @base <png>` | Start from a prepared sheet instead of a blank one |
| `// @source <png>` | Embed a small PNG as `SRC_*` data (up to 62 colours); read it with `srcCrop(x, y, w, h)` |
| `// @layout <json>` | Embed JSON as `LAYOUT` (per-frame boxes made by a prep script) |
| `// @proof-canvas <W>x<H>` | Canvas used by `--proof`; the script sees `PROOF_MODE === true` |

The bundler prepends `tools/art/lib.js` and defines `SPR` (the sprite) for you. Scripts are **ES5
only** (`var`, no arrow functions or template strings). `lib.js` offers:

- `Buf(w, h)` with `px`, `rect`, `ell`, `tri`, `line` and `a` (alpha at a point): an RGBA pixel buffer
- `outlined(buf, colour)`: a copy with a 1 px outline, 2 px larger per axis
- `onto(base, fn)`: draw shading that cannot spill past a shape
- `blit(dst, src, x, y)`: copy opaque pixels
- `srcCrop(x, y, w, h)`: read a region of the embedded source PNG

A typical script draws each frame into a cell-sized `Buf` (base layer first, then the parts that
change), blits it into the sheet buffer, and finishes with
`IMG.putImageData(sheet.d); SPR.save();`. See `tools/art/corgi_desk.js` for a complete example, and
`tools/art/icon.js` for a single-image one.

Generated or traced references can go through `tools/art/prep_sheet.py` first (see the README's
Characters section). Keep references out of the repo unless you own them; commit only the prepared
base sheet.

## 6. Try it in the app

```powershell
godot --headless --path . --import                                  # first run, imports the new PNG
godot --path . -- --pack=<id>                                       # run with your pack
godot --path . -- --pack=<id> --preview=attention                   # hold one animation forever
godot --path . -- --pack=<id> --preview=<break> --screenshot=out.png --screenshot-frames=8
```

`--preview` takes any state your manifest maps (`idle`, `attention`, or a break name). You can also
switch packs at runtime from the right-click menu; the choice is remembered. With your pack running,
check that:

- idle, every break and attention loop without a visible jump from the last frame to the first
- returning from a break or attention to idle does not move the character
- a notification bubble (`./scripts/test-mcp.ps1`) and the status tray sit cleanly above it
- dragging left and right still looks right when mirrored
- clicking empty space around the art passes through to the window behind

## 7. Pull request checklist

- [ ] `packs/<id>/pack.json`, `sheet.png` and `sheet.png.import` are committed, and `id` matches the folder
- [ ] The pack defines `idle` and `attention` and at least one break; attention is neutral
- [ ] Hard-edged transparency, one outline colour, one shared palette
- [ ] `tools/art/<id>.js` rebuilds `sheet.png` exactly (or explain how the art was made)
- [ ] A row for the pack in the README's Characters table
- [ ] Tests pass: `./scripts/run-tests.ps1` (it validates every bundled pack automatically). Add your
      id to the list in `test_every_message_gets_the_single_attention_animation`
      (`tests/cases/test_notifications.gd`), and add a short pack-specific test next to
      `test_corgi_desk_animations` if you like.
- [ ] A screenshot or GIF of idle, each break and attention in the PR description
- [ ] You have the rights to the art, and the PR says if references were generated
